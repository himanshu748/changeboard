## Authentication contract

The [authentication guide](https://developers.buffer.com/guides/authentication.html) documents authorization-code OAuth with PKCE for all clients. Authorization endpoint: `https://auth.buffer.com/auth`; token endpoint: `https://auth.buffer.com/token`; GraphQL endpoint: `https://api.buffer.com`. Changeboard requests only `account:read`, `posts:read`, `posts:write`, and `offline_access`. Confidential server clients include their secret in token requests; public clients omit it. Refresh tokens rotate and are single-use; reusing one can revoke the grant. No automated token replay is permitted after an ambiguous refresh result. Local disconnect removes credentials; users can revoke the grant through Buffer account settings. No undocumented revocation endpoint is used.

The [app-building guide](https://developers.buffer.com/guides/building-apps.html) requires registered callbacks to match exactly, including HTTPS for localhost. The app is a server application, so confidential-client registration is appropriate; “public-user OAuth” does not require exposing its client secret. The server keeps the verifier/state, atomically consumes the attempt, and must serialize refresh under a per-connection database lock. AES-256-GCM token encryption binds ciphertext to the connection ID. Token responses never enter browser JSON or API receipts.

| Scheduling | [Posts and scheduling](https://developers.buffer.com/guides/posts-and-scheduling.html) | Fixed changes use `mode: customScheduled` and UTC `dueAt`; otherwise both omitted. Domain layer checks calendar semantics and cutoff against a newly observed post |
| Correction draft | [CreatePostInput](https://developers.buffer.com/types/CreatePostInput.html) | Separate `createPost`, `saveToDraft:true`, `needsApproval:false`, `mode:addToQueue`, `schedulingType:automatic`, explicit assets list. | Metadata coverage | [CommonPostMetadata](https://developers.buffer.com/types/CommonPostMetadata.html), [Facebook metadata](https://developers.buffer.com/types/FacebookPostMetadata.html), [Instagram metadata](https://developers.buffer.com/types/InstagramPostMetadata.html) | Read common annotations/type and Facebook/Instagram-specific metadata. | Replacement images | [ImageAssetInput](https://developers.buffer.com/types/ImageAssetInput.html), [ImageMetadataInput](https://developers.buffer.com/types/ImageMetadataInput.html) | New HTTPS image + alt text; old positional tags are never copied. New tags must be explicitly supplied/reviewed, otherwise an empty new tag list is sent |
| Image reads | [ImageAsset](https://developers.buffer.com/types/ImageAsset.html), [ImageMetadata](https://developers.buffer.com/types/ImageMetadata.html) | Source, thumbnail, dimensions, alt text, animation flag and user tags retained in snapshot |
| Public hosting | [Hosting media](https://developers.buffer.com/guides/hosting-media.html) | Buffer fetches direct public media URLs; stable availability must extend through publication. No Buffer upload endpoint. Local assets do not prove public reachability |
| Rate handling | [Rate limits](https://developers.buffer.com/guides/api-limits.html) | Read `RateLimit` and `Retry-After`; block further requests during client cooldown, no automatic writes/retries. Server persists relevant backoff between requests. Published free-plan figures are 100/15min, 250/day, 3,000/30days and one app client; no upgrade or purchase performed |

Both GraphQL top-level errors and mutation error variants are checked. A lost write response, malformed success or GraphQL response with ambiguous partial execution produces an uncertain outcome, never optimistic success. The server executor must reconcile via a fresh read before deciding whether another action is safe. Each call is independent; Buffer-side atomic batches, compare-and-swap and idempotent creation have not been established.

## Live capability gates

The adapter defaults to **no enabled live write formats**. Enabling a format requires a dated `LiveFormatEvidence` record with a receipt ID and key such as `facebook:page:text` or `instagram:business:single-image`. A supported schema alone is not such evidence. Instagram text-only correction is withheld. Before enabling a key, use an authorized owned test channel and valid future fixtures; observe read/edit/read-after-write, metadata/schedule preservation, image handling and correction-draft behavior. Save the redacted request/response and verification outcome. Controlled initial provider verification must be explicitly distinguished from enabling end-user operations.

The optional `onReceipt` callback receives operation, query/variables, response, HTTP status, rate-limit metadata and timestamp. Authorization headers and OAuth exchanges are intentionally excluded. The server retains the latest twelve receipts in the owning connection record; they are excluded from browser state responses. Receipts can contain private captions and must remain scoped to the owner, never printed as public demo evidence without review. Receipt sink failure does not cause a mutation replay. Account switching resolves the token-proven Buffer account to its own local owner; a different Buffer identity never inherits the previous account's local campaign.

The server's durable operation lock/reconciliation tests are separate from these adapter and connection tests. The first concurrent WASM test startup exceeded its hook budget; an isolated rerun after the migration loader repair passed. This is local SQL-engine evidence, not a deployed multi-process PostgreSQL load test. Documentation verification is not schema introspection, a provider contract test or deployment evidence.
